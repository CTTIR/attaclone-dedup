## Validation

Baseline JavaScript parsed, but there were no behavior tests. Synthetic probes
reproduced filename/size automatic deletion eligibility and one annotation save
during dry run. The revised Node suite exercises dry-run zero writes, successful
identity-preserving transfer, transfer/save rollback, inspection failures, stale
content/metadata, permissions/pending edits, invalid selections, native getAll
objects, preview defaults and reentrancy.
The 19 regression tests also cover partial annotation transfer followed by
failure, failed cache recovery, note links created after review, relations,
multi-file snapshot exclusion, and failed reference inspection. Three Python
package tests cover determinism, source/archive equality, refused overwrite and
unexpected-member rejection. Shutdown and enabling dry run cancel pending writes;
disabling dry run during a preview does not turn that scan into an apply operation.

Run `node --test tests/*.test.js`, syntax-check all three JavaScript files, then
build and verify `dist/attaclone-dedup-1.0.1.xpi`. Building twice with the same
source yields byte-identical archives. Different pre-existing archives are
refused, never replaced. The XPI contains only runtime files and the MIT license.

Native API contracts were checked against the installed application's
`app/omni.ja`: `Items.getAll`, `Items.moveChildItems` (transaction-required),
`Item.getAnnotations`, `Item.attachmentHash`, and the Gecko IOUtils hashing API.
The code uses `IOUtils.computeHexDigest(path, "sha256")` and native
`Items.moveChildItems(...,{includeTrashed:true})`; no MD5/name/size fallback is
used for decisions. These checks are distinct from running the plugin in Zotero.

Live qualification in a disposable profile is pending separate integration
verification. No plugin was installed in the user's default profile and no user
library operation was performed during this code audit. No release, update feed,
or DOI was published; CI is prepared but unobserved until pushed.

## Operational limits and Workbench handoff

Use only on a trusted local filesystem with a full data-directory backup. A file
may change externally despite pre/post-hash checks; do not edit attachments while
applying. Empty files, unreadable files, and incomplete metadata are left alone.
Non-PDF attachments, external annotations, and PDFs referenced by notes or
relations are preserved. Note-reference inspection uses a conservative substring
match of the attachment key against library note HTML, including trashed notes;
an incidental key mention can therefore cause a safe false positive. Links in
external applications cannot be inventoried here. Broad relation/note migration
and other file formats remain outside this safety release.
Annotation transfer preserves identities but intentionally changes parents;
restoring source attachments from Trash does not reverse transfers automatically.
Notes/tags are not merged. Manual review defaults to retaining all copies.

Finish live Zotero work before Workbench reads. After deduplication, close Zotero
and refresh Workbench extraction/audit; its previous manifest describes the old
attachment set. Never run two mutating plugins concurrently. The manifest's
compatibility declaration is a supported-target boundary, not proof of every UI
path in every operating system.
